# ADR-002 每任务一个浏览器实例，而不是全局共享

## 背景

Agent 执行任务要操作浏览器。浏览器实例怎么管理，直接影响隔离性、并发能力和故障影响面。

## 候选方案

1. **每任务新建整个 Browser，任务结束关闭**（v0.1 采用）
2. 全局共享一个 Browser，所有任务共用（省资源）
3. 全局共享 Browser + 每任务新建 BrowserContext（生产常见折中）
4. 浏览器池 + 任务调度（工程量大）

## 决定

v0.1 用方案 1；P3 上并发时演进到方案 3。

## 理由

- 方案 1 隔离最彻底：cookie / 本地存储 / 权限都随实例销毁，任务间不会串状态
- 失败可复现：每个任务从干净环境开始，踩坑日志里的失败才能重放
- 一个任务崩溃不会连坐其他任务；实现也最简单
- 代价是每次启动 1~2 秒、内存占用更高——v0.1 单用户单任务，这个代价无所谓

## 后果

- P3 引入队列/并发后，必须换方案 3：共享 Browser 省启动开销，每任务一个 Context 保持隔离
- 切换时只改 `BrowserSession.start()`，动作层和 Agent 层不用动
- 需要补一条 ADR 记录切换时的实测数据（启动耗时、内存、并发数）

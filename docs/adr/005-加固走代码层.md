# ADR-005 加固走代码层，不走提示词

## 背景

隔离评测集（`scripts/eval_holdout.py`，10 个与提示词无重合的任务）基线 **70%**，
三个固定失败点每次复现：

| 任务 | 失败表现 | 真实根因 |
|---|---|---|
| H3 分类去重 | 答"分类"（表格列标题）/ 把商品名当分类数 | 能力上限：不会合并同类项 |
| H4 筛选后取集合 | 输入关键词后**没点按钮**就作答，拿全表当结果 | 多步被压成一步 |
| H6 往返导航 | detail ↔ detail2 来回点，走满被判 loop | 跳转后**沿用上一轮编号**（detail2 的 e1 是"上一页"） |

## 三次实验（同一 holdout，判定口径不变）

| 版本 | 改动 | 隔离集通过率 |
|---|---|---|
| v1 | 基线（判断优先 + 3 个 few-shot） | **70%（14/20，两轮失败点完全相同）** |
| v2 | 加【多步任务】plan/progress 结构 + 统计/筛选规则（约 400 token） | 60%（12/20） |
| v3 | v1 + 两条针对机制的短规则（编号重排、搜索两步） | 60%（12/20）**并把原本通过的 H1 弄挂了** |

v2/v3 的失败不是"没生效"，是"反效果"：H1（数下拉选项）在 v3 下变成 loop，
H3 从答"分类"变成列一串商品名——模型注意力被新增文字挤走了。

## 决定

**不在提示词里继续加固**，保持 v1（70%）。后续加固只走两条：

1. **代码层兜底**（不改 prompt 长度）
   - 编号漂移：快照侧给"跨轮稳定"的辅助标识（例如元素 text + role 的指纹），
     动作校验时若目标 text 变了就回喂"编号已重排"，而不是让模型自己记住
   - 多步：workflow 侧对"输入后未点按钮"这类形态做检测（页面没变化 + 输入框 value 已变 → 提示具体缺哪一步）
2. **评测驱动**：任何改动必须跑 holdout（建议 2 轮，因为这套集合的失败点非常稳定，
   单轮 10 次的方差≈0，但改 prompt 后表现会整块跳变）

## 理由

- `glm-4-flash` 的指令遵循"预算"极小：v2 加了约 400 token 规则掉 10 个点，v3 只加两行也掉 10 个点。
  **同样的信息换成代码执行，不占 prompt 预算**。
- 弱模型的失败模式是"忘记整体结构"，而不是"不懂某条规则"。用规则补结构，方向就错了。
- 换模型能立刻解决（实测 glm-4.5-flash 一次就对），但当前约束是只用免费档，故搁置。

## 后果

- ✅ 有一个可复现的度量：70%，失败点稳定，能明确说清"下一步改哪里、预期提升多少"
- ⚠️ H3 这类"合并同类项"是模型能力问题，代码层兜底也只能做到"提示它逐条列"，不保证对
- ⚠️ plan/progress 的管线留在 `workflow.py` 里但**未启用**（提示词已回滚）；
  将来换更强模型时可以重新打开，届时先跑 holdout 验证，别再凭感觉加

# ADR-004 免费弱模型走 few-shot，而不是堆规则或换模型

## 背景

v0.1 用 `glm-4-flash`（免费档，指令遵循最弱）。实测发现同一个要求：

- 写成"规则" → 模型不执行（看到「提交成功」还连点提交）
- 写成"示例" → 模型照着做（一次就 finish）

对照实验数据（同一份快照、同一段 prompt，只改提示词/模型）：

| 方案 | 输出 | 结果 |
|---|---|---|
| glm-4-flash + 动作表前置 + 8 条规则 | `click e3` / `scroll down` | 失败 |
| glm-4-flash + 判断优先 + 5 条规则 | `finish 正确内容`（读取类） | 成功 |
| glm-4-flash + 再加一条"见成功提示就 finish" | `click e6` | 失败 |
| glm-4-flash + 1 个 few-shot 示例 | `finish 提交成功：…` | 成功 |
| glm-4.5-flash | `finish 提交成功：…` | 成功 |
| glm-z1-flash | `finish …`（带 `<think>` 块） | 成功，但更慢、输出需剥离 think |

## 候选方案

1. 继续堆规则，让规则更"强硬"（实测无效）
2. **few-shot：每条任务形态给一个 2~3 行的示例**（v0.1 采用）
3. 换更强模型（glm-4.5-flash / glm-z1-flash）
4. 微调 / 换厂商

## 决定

采用方案 2 作为默认策略；模型保持 `glm-4-flash`，但**模型名走 `.env` 配置**，随时可切。

> 2026-10-23 用户确认：没有其他免费模型可换，暂不考虑付费模型 → 方案 3 搁置，长期走 "flash + few-shot"。若将来加预算，改 `.env` 一行即可切换，代码不用动。

## 理由

- 免费模型是硬约束，方案 3 需要确认额度政策，且成本/延迟不可控
- few-shot 的边际成本低：每个示例 ≈ 40 token，总共 3 个约 120 token
- 规则是"抽象的"，示例是"具体的"。弱模型缺的不是知识，是"照做"的倾向

## 后果

- ✅ T1-T5 五任务全绿（成功率从 0/5 到 5/5，但注意：success 是"模型说完成"，不等于答案正确，M6 要加答案校验）
- ⚠️ 示例只覆盖已见过的任务形态。遇到新形态（比如弹窗、上传、多页表格）大概率退化 → 需要"失败即补示例"的迭代习惯
- ⚠️ 提示词在变长，未来若示例超过 6~8 个应考虑分场景裁剪，否则挤压快照位置

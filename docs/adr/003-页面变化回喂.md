# ADR-003 每轮把"页面变化"回喂给模型，而不是让它自己发现

## 背景

Agent 执行一个动作后，下一轮会重新拍快照。但"快照变了"这件事对模型并不显然：它看到的是两段长文本，要靠自己比对才知道"刚才那下生效了没有"。

T2 实测：提交表单后正文末尾已经出现「提交成功：姓名=张三…」，模型仍然连点 3 次「提交」。T1 实测：点了没有反应的「筛选」后，模型连点 3 次。

## 候选方案

1. **不回喂**，让模型自己从两轮快照里看出差异（现状，实测失败）
2. **计算差异后写进 prompt**（v0.1 采用）
3. 把上一轮快照也塞进 prompt，让模型自己 diff（上下文成本翻倍，且对弱模型更难）
4. 只用规则提示"如果没变化就换个动作"（模型不照做，见踩坑日志第 4 条）

## 决定

采用方案 2。每轮 observe 时用 `_text_delta()` 算差异：

- 页面完全没变 → 注入「上一轮动作执行后页面没有任何变化，说明这个动作无效」
- 页面变了 → 注入「页面已更新，新出现的内容：『…』」，最多 120 字符

## 理由

- 差异是**我们算得比模型准**的信息：字符串比对是确定性的，模型在两段长文本之间做 diff 是概率性的
- 只取"新增"部分：任务完成信号几乎总是"多了什么"（成功提示、结果行、价格表），删掉的内容对决策价值低
- 成本可控：120 字符 ≈ 60 token，比让模型自己推理便宜得多

## 后果

- ✅ 动作生效/无效能被立刻确认，减少无效重试（T2 从 loop 变成功的前置条件之一）
- ⚠️ 差异提取是字符级近似（`difflib`），页面整体重排时 delta 可能很长且噪声大，靠 120 字符上限截断
- ⚠️ 它只解决"不知道自己做了什么"，不解决"知道也不做"——后者是模型能力问题，见 ADR-004

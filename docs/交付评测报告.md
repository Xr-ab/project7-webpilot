## 二、能力评测：本地测试站 10 题 × 3 轮 = 29/30

### 2.1 这 10 题各考什么

每题只考一个能力点，不是凑数（扩题理由写在 `scripts/eval_p1.py` 每个判定函数的 docstring 里）：

| 题 | 考察点 | 期望答案 | 为什么单独考它 |

| T2 | 表单提交 | 回显含张三/邮箱/福州 | 多控件组合 + 结果确认 |
| T3 | 读表判断（集合） | 无线鼠标、USB 集线器 | 集合必须**完全相等**：漏一个错，多一个也错 |
| T4 | 搜索计数 | 1 | 数对了 |

### 2.3 唯一失败的归因：数值比较退化成字符串比较

T10 三次跑，两次答对（显示器 ¥1299），一次答成 `降噪耳机（¥899）`。
把 6 个价格摆出来就明白了：

```
89   299   1299   59   899   129
```

按**数值**比，最大是 1299；按**字符串**比，首字符最大的那一组（`8` 开头）里 `899` 胜出。
模型给出的错误答案正好是字符串序的最大值 —— 它不是"没看见 1299"，而是把数字当成字比较了。

这不是提示词能修的（"请按数值比较"会连带污染别的题，见 6.2 的实测）。
正确方向是**让模型只负责抽结构化数据、由代码算极值**，记在第八节。

## 七、D1 过程中发现并修掉的缺陷（含改前/改后数字）

评测不是"跑一遍记个数"。D1 一共抖出 6 个系统缺陷，每一个都是**先看到失败现象、再定位、
再改**，其中 5 个改完有前后对比：

### 6.1 提示词写了"结论"，但系统没有资格下这个结论

- **现象**：T8（搜 zzz 问几条结果）连点 3 次搜索按钮，判 loop。
- **定位**：`step_observe` 在页面文本没变时提示"上一轮动作执行后页面没有任何变化，
  **说明这个动作无效**"。
- **根因**：搜一个不存在的词时，动作**是生效的**，结果就是"共 0 条结果"，页面当然不变。
  系统只观察到"文本没变"，却断言"动作无效" —— 模型于是判断"那是没点上，再点一次"。
- **修法**：改成只报事实 + 给两条出路（"可能是没生效，也可能这就是正常反应；
  信息够回答就 finish，否则换个动作"）。
- **改前/改后**：T8 **1 次跑 → fail（loop）** ⇒ **3/3 pass**。

### 6.2 加一条提示规则，赔掉三道题（这次最贵的教训）

- **背景**：T9 在 6.1 修完之后仍然挂，失败模式是"跳到别的页面去把不存在的东西找出来"。
- **错误修法**：在提示词里加一条「任务是"能不能/有没有"这类判断时，"没有"也是答案，
  不要跳到别的页面去找」。加完 T9 立刻 3/3。
- **代价**：同一次改动之后跑全量，**T2 1/3、T5 0/3、T6 0/3** —— 三道之前能过的题全挂。
  - T5 答"当前页面没有商品信息"，而价格就写在快照里：新规则被它滥用到非判断题上；
  - T6 的 JSON 开始崩：`{"action":{"type":"type",...}}`，action 被套成了对象，
    两次非法动作后判 invalid_action，提示词变长直接打掉了弱模型的格式稳定性。
- **正确修法（回退规则 + 换机制）**：把规则删掉，改成**动作回显** —— 执行完之后告诉模型
  "刚才点/填的是 e1『上一页』"（见 6.3）。这一次一句规则都没加，T9 3/3、T2/T5/T6 全部恢复。
- **教训**：弱模型的提示词是零和博弈，**加一条规则要付两条的代价**。
  能靠"喂事实"解决的，不要靠"讲道理"。

### 6.3 系统从不告诉模型"你实际点到了什么"

- **现象**：T9 里快照明写 `e1 link 上一页 -> detail.html`，模型 thought 是"点击下一页按钮"，
  照样点 e1，一路往回翻，最后在**第一页**上回答"下一页还能点"。
- **根因**：模型立了意图（"点下一页"）之后，去元素列表里**随便挑一个编号**执行，
  全程不核对编号后面的文字；执行完也没有任何反馈告诉它点错了。
- **修法**：`_apply` 执行完把目标元素的实际文字记进 `action_echo`，下一轮拼进 notice
  （只出现一轮，措辞只报事实、不带训教）。
- **效果**：T9 从"点错按钮走反方向"变成"跳页后发现不对、自己回头"，
  **0/3 ⇒ 3/3**（7 步，比其它题慢，但结论正确）。

### 6.4 few-shot 示例把答案喂给了模型

- **现象**：T9 有一次答出 `Marilyn Monroe` —— 跟本地测试站毫无关系的字符串。
- **定位**：这个字符串来自**我自己写的系统提示示例 4**：「任务要作者名……刚点完下一页……
  正确输出：`{"thought":"已经在第2页，正文第一条就写着 by Marilyn Monroe"…}`」。
- **根因**：示例的场景（"刚点完下一页"）和题目场景（"点下一页后判断还能不能继续"）
  高度重合，模型在同一个状态下直接抄了示例的 thought 和 answer。
  **抄示例比读页面省力，弱模型必然抄。**
- **修法**：示例 4 换了场景（改成"打开公告页、全文已在正文里"），答案也换成不会被误当答案的
  中性短句；同时在文件头写下"示例不能和常见任务形态撞场景"的选题纪律。

### 6.5 动作格式报错不给正确形状，模型只能重犯

- **现象**：T6 稳定输出 `{"action": {...}}`（action 套成对象），两次后判 invalid_action，
  **3/3 全挂**。
- **根因**：`parse_raw` 的报错是 `动作格式不对：Input should be a valid string`。
  这句话是给开发者看的英文；模型不知道"该改成什么样"，只能原样再发一遍。
- **修法**：报错里直接摆出可照抄的样例（`"action"` 只能是字符串，参数平铺）。
  顺带一提：第一版改完反而更糟 —— 模型照着错误信息的新词造出了 `{"type":"type",...}`，
  所以文案要"给样例"而不是"给术语"。

### 6.6 Windows 上原子写会撞上"有人正在读"（非能力问题，但会算进成功率）

- **现象**：T3 第 3 轮 `status=error`、0 步、空答案。第一版评测报告把它归到"答案错误"，
  差点当成模型问题写进报告。
- **定位**：`meta.json` 里 `note = "PermissionError: [WinError 5] 拒绝访问。meta.json.tmp -> meta.json"`。
- **根因**：落盘用"写 .tmp 再 rename"保证原子性。**Windows 上目标文件只要被别的进程打开着
  （API 每秒轮询读 meta.json），rename 就失败**；POSIX 上 rename 不受影响，
  所以只在本地 Windows 复现，容器里跑一万次也看不到。
- **修法**：`_write_json` 对 `replace` 重试 6 次（10/20/…/60ms，最坏等 210ms），
  失败到底则清理 .tmp 后如实抛出。**加锁是错的**：写方只有一个，冲突是瞬时的，加锁会把
  瞬时竞争变成排队。
- **连带修**：评测脚本补记 `note` 字段并单独列出"失败明细（判定原因 + 后端说明）"——
  否则环境错误会被当成能力失败写进报告，这是评测报告最容易出的假账。

### 6.7 一次未能复现的运维现象（如实记录）

正式跑第一轮时，T1 出现 `status=timeout`、0 步、`started_at=None`、耗时 180.9s。
worker 日志显示任务**被取到了**（`delayed=7.87s`），跑了 181.46s 被超时杀掉。

之后专门做了实验：重启 worker 后**立刻**提交一个任务 → 6 秒正常完成，**没有复现**。
推断是上一次强杀 worker 时浏览器进程残留、占着 profile 锁。
未定论，写在这里而不是藏起来；缓解见第九节（启动顺序与优雅停止）。

## 八、诚实的边界说明（这些数字不能当泛化能力读）

1. **样本小**：能力评测只有 30 次样本，一次失败就差 3.3 个百分点。
   T10 的 2/3 与真实情况（约 7 成）之间的差距，就是小样本的抖动。
2. **作者看过这 10 道题**：D1 全程是我在调试，题目和提示词我都看过、改过。
   这个 96.7% 度量的是"在这套可控站点上的稳定性"，**不是"面对陌生网站的泛化能力"**。
   想看泛化，只能看第三节的真实站点（50%）—— 那才是没有被我调过的场景。
3. **任务是单步/少步**：平均 3.4 步。真实业务的浏览器任务动辄 10+ 步，
   步数一长，每一步的错误率会复合，成功率是**乘**出来的。
4. **免费档模型**：GLM-4-Flash 是零成本档，能力上限就摆在那里。
   数值比较、否定判断这两处短板换更强模型能直接改善，但本项目刻意从免费档起步。

**下一步该做什么（按性价比排序）**：

| 优先级 | 改进 | 针对的问题 |
|---|---|---|
| 高 | 让模型输出结构化数据（抽成 JSON 列表），**极值/求和等计算交给代码** | T10 的数值比较退化 |
| 高 | 位置类信息写进块正文（`[3/10]`），或检索时按序号重排 | RAG 的 Q8 |
| 中 | 动作回显升级为"跳页后强制重读元素文字"（现在靠提示，可以做成硬校验） | 真实站点 R3 |
| 中 | 快照元素上限 80 → 分层（先给分组概览，再按需展开） | 真实站点 R4 |
| 低 | 冷启动预热（提交评测前先跑一个空任务） | 6.7 的超时 |

## 九、启动 / 停止的正确姿势（6.7 的缓解）

```bash
# 顺序：先库和 Redis，再 API，最后 worker（worker 要连 Redis 队列）
docker start wp-postgres wp-redis

# API
cd backend && <venv python> -m uvicorn app.main:app --port 8000

# worker（模块名是 arq 的子命令，别写成 python -m app.worker，那样会静默退出 0）
cd backend && <venv python> -m arq app.worker.WorkerSettings

# 停止：先停 worker（Ctrl+C 优雅退出），再停 API
# 不要用 kill -9 / Stop-Process -Force 杀 worker：Chromium 子进程会留下来占 profile 锁
```
